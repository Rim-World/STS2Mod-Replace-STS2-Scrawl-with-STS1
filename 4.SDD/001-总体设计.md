# 总体设计：ScrawlReplacementMod

- 工程：`9.SRC/ScrawlReplacementMod`
- 版本：1.0
- 适配：游戏 `default v0.107.1` / `public beta v0.111.0`，Windows（发布包为 MSIL，理论跨平台）

## 一、设计目标

1. 把 STS2 无色金卡「潦草急就」（`MegaCrit.Sts2.Core.Models.Cards.Scrawl`）整卡替换为 STS1 同名卡样式：
   升级效果改为费用 1→0（不再获得保留），卡名、描述、卡图改用 STS1 资源。
2. 不新增卡牌、不禁用原卡：所有改动都作用在原卡实例上，关闭 mod 后即恢复原状。
3. 最小补丁面：只覆盖升级行为与三处展示 getter，基础版行为不动。
4. 单份 DLL 同时适配 107 与 111 两个游戏版本。
5. 资源加载失败不得导致游戏崩溃。

## 二、模块划分

| 模块 | 文件 | 职责 |
|---|---|---|
| 模组入口 | `ModEntry.cs` | `[ModInitializer("ModLoaded")]` 标记的静态入口；创建 `Harmony` 实例并 `PatchAll`；定义 `ModId` 与卡图 pck 路径常量 |
| 开关 | `ModConfig.cs` | 静态只读开关 `IsReplaceEnabled`（当前恒为 `true`）；每个补丁在执行前都检查该开关 |
| 卡图加载 | `PortraitTextureLoader.cs` | 懒加载卡图纹理；pck 资源优先，失败回退到 DLL 内嵌 PNG；结果缓存于静态字段 |
| 升级补丁 | `Patches/ScrawlOnUpgradePatch.cs` | `Scrawl.OnUpgrade` 的 Prefix，整体替换升级行为 |
| 文本补丁 | `Patches/ScrawlTextPatches.cs` | `CardModel.TitleLocString` / `CardModel.Description` getter 的 Postfix，切换到模组文本键 |
| 卡图补丁 | `Patches/ScrawlPortraitPatches.cs` | `CardModel.Portrait` / `PortraitPath` / `PortraitPngPath` getter 的 Prefix，返回 STS1 卡图 |
| 本地化资源 | `ScrawlReplacementMod/localization/<lang>/cards.json` | 15 个语言目录，各含 `RE_SCRAWL.title`、`RE_SCRAWL.description` 两个键 |
| 卡图资源 | `ScrawlReplacementMod/images/card_portraits/{,big/}scrawl.png` | 手持卡图 250×190 与大图 1000×760，由 pck 打包 |
| 内嵌兜底 | `assets/scrawl_big.png` | 作为 `EmbeddedResource` 编入 DLL（`LogicalName` = `ScrawlReplacementMod.assets.scrawl_big.png`） |
| 模组图标 | `ScrawlReplacementMod/mod_image.png` | Godot 工程图标 / 创意工坊示意图 |
| 工程与构建 | `ScrawlReplacementMod.csproj`、`project.godot`、`export_presets.cfg`、`build.ps1` | .NET 9 + Godot 4.5.1 mono 工程定义、导出预设与一键构建脚本 |

依赖关系：`ModEntry` → `Patches/*` → (`ModConfig`, `PortraitTextureLoader`, `ModEntry` 常量)；
`PortraitTextureLoader` → `ModEntry.ModId`。补丁模块之间互不依赖。

## 三、补丁策略

Harmony 补丁全部使用特性声明，由 `ModEntry.ModLoaded` 中的 `_harmony.PatchAll(...)` 一次性安装，
共 6 处：

| 目标 | 类型 | 处理 |
|---|---|---|
| `Scrawl.OnUpgrade` | Prefix | 调用 `__instance.EnergyCost.UpgradeBy(-1)` 后返回 `false`，不执行原方法（原方法会 `AddKeyword(CardKeyword.Retain)`） |
| `CardModel.TitleLocString`（getter） | Postfix | 实例为 `Scrawl` 时把结果替换为 `new LocString("cards", "RE_SCRAWL.title")` |
| `CardModel.Description`（getter） | Postfix | 同上，键为 `RE_SCRAWL.description` |
| `CardModel.Portrait`（getter） | Prefix | 实例为 `Scrawl` 时返回 `PortraitTextureLoader.Get()` |
| `CardModel.PortraitPath`（getter） | Prefix | 实例为 `Scrawl` 时返回 `res://ScrawlReplacementMod/images/card_portraits/big/scrawl.png` |
| `CardModel.PortraitPngPath`（getter） | Prefix | 同 `PortraitPath` |

设计取舍：

- 文本与卡图补丁挂在基类 `CardModel` 上而不是 `Scrawl` 上，靠 `__instance is Scrawl` 做实例过滤，
  这样图鉴、卡组列表、战斗内三种渲染路径都能命中同一入口。
- 升级效果复用引擎官方的减费写法（`EnergyCost.UpgradeBy(-1)`，与官方 `ShadowStep.OnUpgrade` 同款），
  不改 `CanonicalEnergyCost`，避免触及基础费用与缓存失效问题。
- 描述文本为 STS1 原文去掉「消耗」句：`Exhaust` 由关键词徽记渲染，文本内再写一次会重复。
- 文本键加 `RE_` 前缀，避免与其它 mod 或后续官方键冲突。
- 所有补丁先判 `ModConfig.IsReplaceEnabled`，为 `false` 时直接放行原方法。

## 四、数据流

1. **加载**：游戏启动 → 调用标记了 `[ModInitializer("ModLoaded")]` 的 `ModEntry.ModLoaded`
   → 新建 `Harmony(ModId)` → `PatchAll` → 日志输出成功或异常。
2. **升级**：升级流程（含图鉴预览的 `MutableClone()` + `UpgradeInternal()`）→ `Scrawl.OnUpgrade`
   → Prefix 拦截 → `EnergyCost.UpgradeBy(-1)` → 费用 1→0；不添加 `Retain`。
3. **文本**：UI 读取 `CardModel.TitleLocString` / `Description` → Postfix 替换为 `RE_SCRAWL.*`
   → 引擎按当前语言从 `localization/<lang>/cards.json` 取值。
4. **卡图**：UI 读取 `Portrait` → `PortraitTextureLoader.Get()`
   → 首次调用：`ResourceLoader.Load<Texture2D>("res://ScrawlReplacementMod/images/card_portraits/big/scrawl.png")`
   → 成功则缓存并返回；失败（异常或返回 `null`）→ `Log.Warn` → 从程序集内嵌资源读 PNG
   → `Image.LoadPngFromBuffer` → `ImageTexture.CreateFromImage` 缓存返回；再失败则 `Log.Error` 并返回 `null`。

## 五、数据结构与接口

- 本地化文件为扁平 JSON，键值均为字符串，例（`zhs`）：
  ```json
  { "RE_SCRAWL.title": "潦草急就", "RE_SCRAWL.description": "抽牌直到将手牌抽满。" }
  ```
- manifest（`ScrawlReplacementMod.json`）：`id`、`name`、`author`、`description`、`version`、
  `has_pck`、`has_dll`、`min_game_version`、`dependencies`、`affects_gameplay`。
- 模组对外的代码接口仅三个：`ModEntry.ModId`（常量）、`ModEntry.PortraitPng`（pck 路径常量）、
  `PortraitTextureLoader.Get()`（返回 `Texture2D?`）。

## 六、异常处理

| 位置 | 策略 |
|---|---|
| `ModEntry.ModLoaded` | 整个打补丁过程包在 `try/catch` 中；异常写 `Log.Error`，mod 失效但不影响游戏启动 |
| `PortraitTextureLoader.Get` | pck 加载与内嵌兜底各自 `try/catch`；用 `_initialized` 保证只尝试一次，失败后不反复打日志 |
| 资源缺失 | 返回 `null` 纹理，交由游戏原有渲染流程处理；不做额外兜底图生成 |

## 七、兼容策略

- `min_game_version = 0.107.1`；`Scrawl` 与 `CardModel.EnergyCost.UpgradeBy` 在 107 与 111 中逐字一致，
  因此单份 DLL 通吃两版（取证见 `3.DOCS/001-T-*`）。
- 不加形状守卫（运行时不检查卡牌费用/关键词形态），依赖 `min_game_version` 与游戏更新后的反编译比对。
- 补丁使用 `Prefix` + `__result`/返回 `false` 的标准写法，不修改私有字段，降低版本漂移风险。
- 键前缀与实例过滤共同保证不影响其它卡牌与 mod。

## 八、性能设计

- 卡图纹理只加载一次，静态缓存；热路径（`Portrait` getter）仅读字段或返回缓存。
- 文本补丁只在 `Scrawl` 实例上构造 `LocString`，其它卡牌直接跳过。
- 无后台线程、无轮询、无每帧逻辑。

## 九、构建与测试方案

构建（`build.ps1`）：

1. `dotnet build ScrawlReplacementMod.csproj -c Debug`（MSIL）→ 产物在 `.godot/mono/temp/bin/Debug/`。
2. `Godot --headless --import --path <工程>` 生成 `.import`/`.ctex` 元数据。
3. `Godot --headless --export-pack "Windows Desktop" <mods>/ScrawlReplacementMod/ScrawlReplacementMod.pck`。
4. 复制 `dll`、`pdb`（若存在）、`json` 到 `<游戏目录>/mods/ScrawlReplacementMod`。

测试方案（来自 `2.PLANS/001-G-*` 第五节，游戏内项目**尚未执行**）：

- 图鉴中潦草急就升级预览为 STS1 样式，0 费、无 `Retain` 徽记。
- 战斗内基础版 1 费打出进消耗区；升级版 0 费打出进消耗区，均抽满手牌。
- 无色分类图鉴滚动无闪动。
- 与既有 PhantomKiller / Reaper / Corpse / CalculatedGamble 等 mod 同开无键冲突。
- `default 107` 实机验证：未记录。

## 十、已知限制与待实施改动

1. **`ind` 语言缺失**：111 新增第 16 种语言 `ind`，本 mod 只做了 15 个语言目录；`ind` 玩家读取
   `RE_SCRAWL.*` 会抛本地化异常。用户决定按 15 语言发布，风险接受。
2. **游戏内验证未完成**：见第九节测试清单，文档中标记为待办。
3. **macOS 构建验证**：产物为 MSIL + pck，理论跨平台，实际验证由用户自行执行。
4. **未来版本漂移**：未加形状守卫；游戏更新后需重新反编译比对 `Scrawl` 与 `EnergyCost.UpgradeBy`。
